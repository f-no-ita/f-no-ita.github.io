# ハニーポットログ保全：設計メモ

記録日: 2026-10-19

---

## 現在の構成（最小動作版）

```
[攻撃者] → /api/admin/panel → Cloudflare KV (hp_* キー, 90日)
                                        ↓ 毎朝03:00 sync
                              ローカル honeypot_log.jsonl（追記専用）
```

### 分離の意味

- KV（Cloudflare）と手元ファイルは別の物理インフラ上にある
- Cloudflare の管理者権限を得ても、ローカルファイルには到達できない
- ローカルに到達するには、この機械への別途アクセスが必要

### 追記専用の担保

- `honeypot_sync.py` は `open(..., 'a')` のみ使用
- 上書き・削除操作なし
- `honeypot_sync_state.json` で重複チェックのみ行い、ファイル本体は書き足す一方

### 限界

- sync 前に KV を消された場合、その分は失われる（sync は1日1回）
- ローカルマシンへの物理アクセスや管理者権限奪取には無力
- 目標：「軽い相手には消えない、本気の相手には手間をかけさせる」

## 将来の強化策（現時点では実装しない）

### ハッシュチェーン

- 各ログエントリに `prev_hash: sha256(前エントリの全内容)` を付ける
- 途中のエントリを削除・改ざんすると、以降のハッシュが全部崩れる
- 改ざんを検出できるが、防ぐことはできない

**実装の条件**
- `honeypot_sync.py` がチェーンを計算する処理を持てばよく、外部サービス不要
- ただし検証ツールも必要になる

**保留理由**: 今は記録があること自体が優先。整合性検証は次のステップ。

---

### 外部ハッシュアンカー

- ハッシュチェーンの先端ハッシュを、定期的に外部（GitHub コミット、Twitter、Nostr 等）に刻む
- 「この時点でこの記録が存在した」を第三者が検証可能な形で証明できる

**実装の条件**
- GitHub Actions か常駐スクリプトが必要
- kagi.json と同様に、一定期間活動がないと Actions が止まる問題がある
- 止まらない仕組みの確認が必要

**保留理由**: ハッシュチェーンより先にアンカーを作っても意味がない。順序として次段階。

---

## 採用・不採用の記録

| 案 | 状態 | 理由 |
|---|---|---|
| KV のみ（同一箱） | 不採用 | 侵入した相手が消せる |
| KV + ローカル JSONL 同期 | **採用** | 最小構成で物理分離を達成 |
| ハッシュチェーン | 保留 | 有効だが今は不要。動く基盤を先に確認する |
| 外部アンカー（Actions） | 保留 | 止まるリスクが高い。kagi.json の前例あり |
| カウンター攻撃・ループ | 明確に不採用 | 三本柱の「追わない」に反する |
